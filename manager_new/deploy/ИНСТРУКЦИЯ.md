# /manager_new/ на боевом сайте — рабочая копия менеджера

Цель: на kupibas.ru появляется `/manager_new/` — копия `/manager/` с новым дизайном.
Работает на **той же базе**: реальные пользователи и КП, создание и правка КП разрешены.

- `/manager/` **только читаем**: его файлы не меняем ни на байт.
- Всё, что создаётся и меняется в `/manager_new/`, сразу видно и в рабочем `/manager/`, потому что база общая.
- Общий шаблон сайта, компоненты и модули не трогаем: от них зависит `/manager/`.

## Шаг 0. Резервная копия

Админка → Настройки → Инструменты → **Резервное копирование** → «Создать резервную копию» (база + файлы).
Нужна на случай, если при работе в `/manager_new/` что-то испортится в данных.

## Шаг 1. Скопировать папку

Админка → Контент → Структура сайта → **Файлы и папки** → корень сайта.

1. У папки `manager` откройте меню (≡) → **Копировать**.
2. Назначение: корень сайта, имя **`manager_new`**.

Права доступа (`.access.php`) копируются вместе с папкой: в копию входят те же менеджеры, клиенты её не видят.

## Шаг 2. Загрузить архив со всем, что сделано в GitHub

1. Скачайте `manager_new.zip`: GitHub → `manager_new/deploy/manager_new.zip` → «Download raw file».
2. Админка → Файлы и папки → откройте `/manager_new/` → «Загрузить файл» → выберите архив.
3. У загруженного `manager_new.zip` откройте меню (≡) → **«Распаковать»** в эту же папку. Затем удалите сам zip.

После распаковки в `/manager_new/` появятся:
- `assets/` — новый дизайн для копии рабочего менеджера (`/manager_new/`, `/manager_new/table/`);
- `2027/` — весь новый интерфейс: рабочий стол-конструктор, конструктор КП (8 шаблонов), справочник, КП клиента, ИИ-помощник, тема, удаление из списка.

**Обязательно — доступ по IP для `2027/`.** В папке `/manager_new/2027/` создайте файл **`ip-allow.php`** с вашими адресами:
```php
<?php return array('1.2.3.4', '5.6.7.8');
```
Свой адрес покажет страница 403 («Ваш IP: …»). Этого файла нет в архиве, поэтому при обновлении он сохранится.
Дополнительно `2027/` пускает только вошедших в Битрикс, имя пользователя берётся из Битрикса.
Новый интерфейс: **`kupibas.ru/manager_new/2027/`**.

## Шаг 3. Подключить дизайн и перенастроить адреса в копии

Откройте на редактирование (как PHP) `/manager_new/index.php` и `/manager_new/table/index.php`.

**Проще:** скопируйте текст этих двух файлов и пришлите мне в чат. Клиентских данных в них нет. Я пришлю готовые версии целиком.

**Самостоятельно:**
1. Сразу после строки `require($_SERVER["DOCUMENT_ROOT"]."/bitrix/header.php");` вставьте содержимое `подключение.php.txt`.
2. В параметрах компонентов замените `"/manager/"` на `"/manager_new/"`. Обычно это `SEF_FOLDER`, ссылки на страницы и пути к шаблонам. Больше ничего не меняйте.

## Шаг 4. Проверка

- `kupibas.ru/manager_new/` открывается, вверху плашка «Новый менеджер /manager_new/», видны реальные КП.
- `kupibas.ru/manager_new/table/` открывается.
  - Если 404: эта страница работает через ЧПУ. Нужна копия правила в «Настройки → Настройки продукта → Обработка адресов» с `/manager/` на `/manager_new/`. Напишите мне — подскажу точное правило.
- Выход из админки → `/manager_new/` просит вход, как и `/manager/`.
- `kupibas.ru/manager/` работает как раньше.

## Откат (1 минута)

1. Удалить папку `/manager_new/` (или только `/manager_new/2027/`, чтобы убрать новый интерфейс).
2. Если добавляли правило ЧПУ для `/manager_new/`, удалить его.

`/manager/`, шаблон сайта и компоненты не менялись, откатывать их не нужно.
Данные, созданные или изменённые через копию, остаются в базе, как если бы их сделали в `/manager/`. Для полного отката данных — резервная копия из шага 0.

## Дальше

Код по-прежнему ведём в GitHub (`manager_new/`). На сайт выкладываем только в `/manager_new/`.
Архив пересобирается командой `sh tools/make-deploy.sh` (`deploy/manager_new.zip`). Для обновления загрузите и распакуйте его поверх: файл `2027/ip-allow.php` со списком IP при этом сохранится.
